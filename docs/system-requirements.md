# 動作環境の要件

AQUA-DRIFT Simulator を動かすための環境要件です。数値の根拠を「実測」「試算」「推奨（未計測）」で
区別しています。実測環境：Intel Xeon 2.1 GHz・2 コア・8 GB（開発環境）、GitHub Actions `ubuntu-latest`
（CI、ソフトウェア WebGL）。

## 1. 構成と前提

| 項目 | 内容 |
|---|---|
| 実行方式 | Docker Compose による複数コンテナ構成（サーバー）＋ Web ブラウザ（表示端末） |
| コンテナ | `db`（PostgreSQL 16 / PostGIS 3.4）、`api`、`clock`、`current-field`、`target`、`observer` ×N（既定 12 = 初期 4＋待機 8）、`doppler`、`deployer`、`estimator`、`web`（nginx＋CesiumJS 1.129） |
| サーバーと表示端末 | 同一 PC でも、LAN 上の別 PC でも可 |
| 通信 | ブラウザ → サーバーの TCP 8090（画面・API・WebSocket）。8091（API 直接）は既定でサーバー自身からのみ |

## 2. サーバー（Docker を動かす PC）

### 2.1 ソフトウェア

| 項目 | 要件 | 備考 |
|---|---|---|
| OS | Linux（x86-64）、Windows 10/11（Docker Desktop・WSL 2）、macOS（Docker Desktop） | Linux x86-64 は CI で起動まで検証済み |
| Docker Engine | 24 以上 | |
| Docker Compose | v2.20 以上（`docker compose` コマンド） | `deploy.replicas`・`cpus`・`healthcheck.start_period` を使用 |
| CPU アーキテクチャ | x86-64 推奨 | Apple Silicon（arm64）では、公式 `postgis/postgis` イメージに arm64 版がないタグがあり、エミュレーションで動作し遅くなる場合がある（未検証） |
| インターネット接続 | **初回ビルド時のみ必要**（Docker Hub・PyPI・npm からイメージとパッケージを取得） | 実行時はオフラインで動作（背景地図 Natural Earth II は同梱、外部タイル不使用） |

### 2.2 ハードウェア

| 項目 | 最小（観測者 12 台・既定構成） | 推奨（観測者 12〜30 台） | 観測者 100 台 |
|---|---|---|---|
| CPU | 4 コア（x86-64、2 GHz 以上） | 4〜8 コア | 8 コア以上 |
| メモリ（Docker に割当） | 4 GB | 8 GB | 12 GB 以上（ホスト 16 GB 以上） |
| ストレージ空き | 10 GB | 20 GB 以上（SSD） | 40 GB 以上（SSD） |

**根拠**

- **推定処理（実測、粒子数 6000、2 スレッド）**：1 秒ごとの処理は平均 152 ms（観測者 4）〜 267 ms（観測者 100）、
  ピーク時メモリ 306〜398 MB。10 秒ごとの粒子の再配置処理では 1.5〜2.6 秒かかるが、推定器は観測を
  まとめて追いかけるため実時間に追従する（その間、画面の推定値が最大約 2 秒遅れる）。推定コンテナは
  既定で CPU 2 コアに制限（`ESTIMATOR_CPUS`）しており、残りのコアを API・観測者・DB・ブラウザに使う。
  このため 2 コアの PC では、同じ PC でブラウザを使うと画面がカクつきやすい。
- **その他のコンテナのメモリ（試算）**：Python のシミュレーション部品だけで 1 プロセス約 33 MB（実測）。
  通信ライブラリを含め 1 コンテナ 50〜80 MB とすると、既定構成の軽量コンテナ 17 個で約 1〜1.4 GB、
  API 約 0.2〜0.3 GB、推定 約 0.4 GB、DB 約 0.2 GB、合計 約 2〜2.5 GB。観測者 100 台では約 +5〜7 GB。
- **観測者 100 台の上限要因（試算）**：各観測者コンテナは毎秒 10 回、全観測者を含む状態（100 台で約 31 KB）を
  API から取得する。100 台では毎秒約 1000 回・約 30 MB の応答生成となり、推定処理より **API の CPU が先に
  上限** になる見込み。Docker 上での 100 台の通し動作は**未検証**。

### 2.3 ストレージの増え方（試算）

イベント履歴（DB）は追記のみで、自動では削除されません。

| 記録 | 観測者 12 台 | 観測者 100 台 |
|---|---|---|
| 推定結果（10 秒ごと、航跡を含む。長時間運転時は 1 件最大約 1 MB） | 最大 約 0.4 GB/時 | 最大 約 0.4 GB/時 |
| 観測者の状態・航跡（毎秒） | 約 0.03 GB/時 | 約 0.25 GB/時 |
| ドップラー観測（毎秒） | 約 0.02 GB/時 | 約 0.17 GB/時 |
| 合計（索引等を含む目安） | **約 0.5 GB/時** | **約 1.1 GB/時** |

Docker イメージとビルドキャッシュに約 2〜3 GB（試算）。履歴を消して初期化するには
`docker compose down -v`（DB ボリュームを削除）。

### 2.4 ネットワーク

| 項目 | 要件 |
|---|---|
| ポート | 8090/TCP（Web 画面、既定で全インターフェースに公開：`WEB_BIND`）、8091/TCP（API、既定でサーバー自身のみ：`127.0.0.1`） |
| 帯域（表示端末 1 台あたり） | 約 6〜8 KB/秒（実測、圧縮前。通信圧縮でさらに縮小）。LAN 越しの表示も可 |
| セキュリティ | **認証機能はありません**。信頼できるネットワーク内で使用するか、`WEB_BIND=127.0.0.1` でサーバー自身からのみに制限してください |

## 3. 表示端末（ブラウザ）

### 3.1 ブラウザ

| 項目 | 要件 |
|---|---|
| 対応ブラウザ | Google Chrome / Microsoft Edge 98 以上（推奨：最新版）、Mozilla Firefox 94 以上、Safari 15.4 以上 |
| 必須機能 | WebGL 2（CesiumJS 描画・MSAA）、Web Worker、WebSocket、`structuredClone` |
| 設定 | ハードウェアアクセラレーションを有効にする（無効だとソフトウェア描画になり、画面に警告を表示） |
| 検証状況 | ヘッドレス Chromium（CI、ソフトウェア WebGL）で全機能の動作を自動確認。他ブラウザは未検証 |

### 3.2 ハードウェア

| 項目 | 最小 | 推奨 |
|---|---|---|
| GPU | WebGL 2 対応 GPU（ソフトウェア描画でも動作するが遅い） | 最近の内蔵 GPU（例：Intel Iris Xe、Apple M シリーズ）または単体 GPU（推奨値、実機未計測） |
| 画面 | 横 1280 ピクセル以上 | 横 1600 ピクセル以上、フル HD 以上 |
| メモリ | 4 GB | 8 GB 以上 |
| CPU | 2 コア | 4 コア以上（サーバーと同じ PC なら 8 コア以上） |

**根拠（実測）**

- ソフトウェア描画（CI の SwiftShader）でも全機能が動作。フレーム間隔は平均 35〜60 ms で、視点移動直後に
  1 フレーム 3〜6 秒かかることがある。描画が追いつかない場合、品質は自動で下がり、なめらか表示は
  自動で停止する。
- 画面側の 1 回の更新処理は平均 6.8 ms（最大 33 ms）、受信データの解読は Web Worker 内で 0.2 ms。
- 画面レイアウトは横 1280 px と 1600 px で横方向のはみ出しがないことを確認済み。横 760 px 未満では
  縦並びの簡易レイアウトになる。

### 3.3 描画が重いときの調整

| 対処 | 操作 |
|---|---|
| 描画品質を下げる | ツールバー「品質」を「中」「低」に固定 |
| なめらか表示を切る | ツールバー「なめらか」をオフ |
| 重い表示を切る | 背景地図・海面をオフ（既定でオフ）、「表示・観測者」タブでボクセルを「点」に |
| 状態の確認 | ツールバー「性能」で fps・更新処理時間・受信量・GPU 名を表示（GPU 名に SwiftShader 等と出る場合はハードウェアアクセラレーションが無効） |

## 4. 主な設定値（`.env`）

| 変数 | 既定 | 内容 |
|---|---|---|
| `OBSERVER_REPLICAS` | 12 | 観測者コンテナ数（初期 4 台＋待機）。1〜100 |
| `ESTIMATOR_CPUS` | 2 | 推定コンテナの CPU 上限 |
| `ESTIMATOR_THREADS` | 2 | 推定の数値計算スレッド数 |
| `WEB_BIND` / `WEB_PORT` | 0.0.0.0 / 8090 | Web 画面の公開先 |
| `API_PORT` | 8091 | API の公開ポート（127.0.0.1 のみ） |
| `ESTIMATION_AUTOSTART` | true | 起動時に推定を自動開始 |
| `MAX_SLANT_RANGE_YD` | 6000 | 上限斜距離の初期値 |

## 5. 未検証事項

- 実機 GPU での描画性能（推奨 GPU は未計測の推奨値）
- Windows・macOS（特に Apple Silicon）での Docker 動作
- Chrome 系以外のブラウザ
- 観測者 100 台構成の Docker 上での通し動作（API 負荷が上限要因になる見込み）
